DATE CONVERSION FUNCTIONS:-
===========================
Oracle provided following date conversion functions. These are
1. To_char()
2. To_date()
3. TO_number()
 
1. to_char():-It is used to convert date type 
============  into character type.

.it can be used to convert date formats like oracle date format to 
 india date format.

.it can used to get part of the date like year,month,date,weekday..etc

Syntax:-
======
to_char(datedatatype,'format')

Eg:-
=====
SQL> select to_char(sysdate,'dd/mm/yy')from dual;

      15/02/25


Note:- Basically to_char character formats are case sensitive formats.
=====

Eg:-
====
SQL> select to_char(sysdate,'DAY')from dual;

     SATURDAY

====
SQL> select to_char(sysdate,'DY')from dual;

Eg:-
====
SQL> select to_char(sysdate,'D')from dual;

In two special cases we are not required to use to_date():-
============================================================
1.sysdate we are using means then we are not required to use
 to_date().

2.Any date datatype column is there in that case to_date() not required.

2. to_date():- It is used to convert date string into 
============  oracle date type(oracle date format)


EX:-
====
SQL> select to_date('27/JUNE/05') from dual;

     27-JUN-05

EX:-
====
SQL> select to_date('27/06/05') from dual;

     Error:not a valid month

NOTE:-Whenever are using to_date() function then passed parameter return
====  values must match with the default date format return values. then 
oracle server automatically converts date string into oracle date type
Otherwise oracle server returns an error.

   To overcome this problem then we must use second parameter as same
as first parameter format then only oracle server automatically internally
converts date string into date type.

Solution:-
=========
SQL> select to_date('27/06/05','DD/MM/YY') from dual;
 
          27-JUN-05

   requirement format using to_char()

SQL> select to char('15-JUN-05','DD/MONTH/YY') from dual;

Error: invalid number

Whenever we are using to_char() always first parameter must be oracle 
understandable format---->oracle date type
 

Solution:-
========
SQL> select to_char(to_date('15-JUN-05'),'DD/MONTH/YY') from dual;

     15/JUNE  /05

  in oracle Whenever we are using to_char() month format then oracle server 
internally automatically allocates maximum 9 bytes of memory into 
month field.

 whenever your passed month having less than 9 bytes then oracle server 
automatically generates gaps in place of remaining bytes.to overcome this
problem if we want to fill those gaps then oracle provided FM(fill 
mode) format within to_char() function. This FM mode not only filling GAPS
but also internally supress leading zeros.



SQL> select to_char(to_date('15-JUN-05'), 'DD/FMMONTH/YY') from dual;


      15/JUNE/05

that case Infront of this one to_date() infront of this one to_char().

*inserting dates into oracle date datatype column:-
==================================================
Syntax:-
======
columnname date
 
 In Oracle whenever we are passing date string into oracle insert statement
then we are not required to use to_date() explicitly because in this case 
oracle server internally uses implicit convertion but here passed parameter 
return values must match with default date format return values.Otherwise oracle 
server returns an error. To overcome this problem also then we must 
use to_date().

Eg:-
====
SQL> create table test(col1 date);
SQL> insert into test values(sysdate); 
SQL> select * from test;

COL1
------------
26-FEB-25

IMPLICIT CONVERSION
====================

SQL> insert into test values('14-FEB-25'); 
SQL> select * from test;

COL1
------------
16-FEB-25
14-FEB-25

EXPLICIT CONVERSION
===================

SQL> insert into test values('22-08-24');
Error: not a valid month
SQL> insert into test values(to_date('22-08-24','DD-MM-YY'));
1 row inserted

SQL> select * from test; 
COL1
------------
16-FEB-25
14-FEB-25
22-AUG-24
